# SLO (Service Level Objective) — 台账系统

## 可用性目标

| 等级 | SLO | Error Budget | 适用场景 |
|------|-----|-------------|----------|
| **台账API** | 99.5% | 43.8小时/年 | 查询/健康检查 |
| **备份任务** | 99.9% | 8.76小时/年 | 每日备份 |
| **监控告警** | 99.9% | 8.76小时/年 | 告警触达 |

## Error Budget 计算

```
99.5% 可用性 = 每年允许 43.8 小时不可用
  = 每月 3.65 小时
  = 每天 7.3 分钟
```

## SLO 仪表盘指标

| 指标 | 来源 | 告警阈值 |
|------|------|----------|
| 可用率 | health endpoint 每分钟探测 | <99% 告警 |
| P99延迟 | uvicorn access log | >500ms 告警 |
| 备份成功率 | backup_daily.sh exit code | 连续2天失败告警 |
| 错误率 | Sentry exception count | >10/min告警 |

## 违规处理

- Error Budget 用尽 → 冻结新功能部署，只修bug
- SLO 连续3天违规 → 触发根因分析
- 备份连续2天失败 → 自动飞书告警
